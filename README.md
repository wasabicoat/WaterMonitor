# เฝ้าระวังระดับน้ำ เจ้าพระยา (Chao Phraya Water Monitor) 🌊

แดชบอร์ดเฝ้าระวังระดับน้ำและศูนย์รวมกล้อง CCTV ริมแม่น้ำเจ้าพระยาแบบเรียลไทม์ ครอบคลุมตั้งแต่เส้นทางน้ำหลากต้นน้ำเจ้าพระยา (นครสวรรค์, ชัยนาท, สิงห์บุรี, อ่างทอง, อยุธยา) สู่พื้นที่ตอนล่าง (ปทุมธานี, รังสิต, ปากเกร็ด, นนทบุรี และกรุงเทพมหานคร)

---

## ✨ ฟีเจอร์หลัก (Features)

### 1. กล้องสดและภาพถ่ายทอดสด (Live Streams & Cameras)
* **กล้องสตรีมสดท่าน้ำนนทบุรี**: ฝังตัวเล่นทางการ (MediaMTX) ของ First Tech ผ่าน iframe — ไฟล์วิดีโอของสตรีมไม่มี CORS header จึงเล่นด้วย hls.js จากหน้าเว็บเองไม่ได้
* **กล้องสตรีมสดท่าน้ำเทศบาลเมืองปทุมธานี**: สตรีมสดจากกล้องริมแม่น้ำเจ้าพระยา
* **ถ่ายทอดสด Facebook Live ท่าน้ำท่าอิฐ**: ติดตามสถานการณ์น้ำท่วมสดจากหน่วยงานท้องถิ่น
* **เล่นอัตโนมัติเมื่อเลื่อนมาเห็น**: วิดีโอทั้ง 3 ตัวเริ่มเล่นเมื่ออยู่บนจอ หยุดเมื่อเลื่อนพ้นหรือสลับแท็บ และโหลดใหม่ตามรอบ (`data-refresh` เป็นนาที) เพื่อแก้ภาพค้าง
* **กล้องวัดระดับน้ำรังสิต–ปทุมธานี (AI OpenCV)**: แสดงภาพสแนปช็อตกล้องวัดระดับน้ำ (เช่น สะพานแดง, เมืองปทุม) พร้อมผลอ่านระดับน้ำอัตโนมัติด้วย AI และระดับเตือนภัย (ปกติ / เฝ้าระวัง / เตือนภัย / วิกฤต) จากระบบ CDP เทศบาลนครรังสิต
* **ตารางกล้อง CCTV เทศบาลนครนนทบุรี (>30 กล้อง)**: แยกตามโซนประตูระบายน้ำและจุดเสี่ยง (โซน A / B) พร้อมระบบค้นหาและ Lightbox ดูภาพขยายขนาดใหญ่
* **ศูนย์รวมลิงก์กล้องและแผนที่น้ำท่วม (Flood & Camera Hub)**: รวมลิงก์ตรงไปยังศูนย์กล้องลุ่มน้ำเจ้าพระยา (กรมชลประทาน), กล้องถนนปากเกร็ด, กล้องจราจรรังสิต, กรมทรัพยากรน้ำ, แผนที่น้ำท่วม 7 วัน GISTDA และ รู้ทันน้ำ

### 2. ข้อมูลระดับน้ำและการพยากรณ์ลุ่มน้ำ (Water Levels & Basin Forecasting)
* **เส้นทางน้ำหลาก ต้นน้ำเจ้าพระยา → นนทบุรี**: แดชบอร์ดติดตามปริมาณน้ำไหลผ่าน (ลบ.ม./วินาที) และ % เทียบกับความจุลำน้ำ (Qmax) เรียงตามลำดับต้นน้ำลงสู่ปลายน้ำ:
  $$\text{C.2 (นครสวรรค์)} \longrightarrow \text{C.13 (เขื่อนเจ้าพระยา)} \longrightarrow \text{C.3 (สิงห์บุรี)} \longrightarrow \text{C.7A (อ่างทอง)} \longrightarrow \text{C.35 (อยุธยา)} \longrightarrow \text{CPY014 (ปทุมธานี/นนทบุรี)}$$
  *(ใช้สำหรับคาดการณ์มวลน้ำที่จะเดินทางมาถึงพื้นที่นนทบุรี-กทม. ในอีก 2–4 วัน)*
* **สถานะ 4 เขื่อนหลักลุ่มน้ำเจ้าพระยา**: รายงาน % ปริมาณน้ำกักเก็บ, ปริมาณน้ำระบาย และปริมาณน้ำไหลเข้า ของเขื่อนภูมิพล, เขื่อนสิริกิติ์, เขื่อนแควน้อยบำรุงแดน และเขื่อนป่าสักชลสิทธิ์
* **สถานีท่าน้ำปากเกร็ด (หัวถนน)**: ระดับน้ำ ม.รทก. พร้อมเกจวัดระดับการเตือนภัย (ปกติ / เฝ้าระวัง / วิกฤต)
* **กราฟระดับน้ำย้อนหลัง (Chart.js)**: ดึงข้อมูลประวัติระดับน้ำย้อนหลัง ทั้งแบบรายวัน (24 ชม.), รายสัปดาห์, รายเดือน, รายปี และทุกปี
* **สถานีโทรมาตร สสน. (ThaiWater) จังหวัดนนทบุรี**: ข้อมูลระดับน้ำและกราฟย้อนหลัง 48 ชั่วโมง
* **ตารางสถานีวัดระดับน้ำลุ่มน้ำเจ้าพระยา**: ข้อมูลครอบคลุม 4 จังหวัด (นนทบุรี, ปทุมธานี, อยุธยา, กทม.) พร้อมตัวกรองแยกจังหวัด
* **ตารางข้อมูลประตูระบายน้ำ**: ระดับน้ำหน้าประตู / ท้ายประตูระบายน้ำสำคัญ
* **ตารางสถานีวัดระดับน้ำเทศบาลนครนนทบุรี (41 สถานี)**: แสดงระดับน้ำหน้า/ท้ายประตู, ระดับน้ำผิวถนน และปริมาณฝนสะสมประจำวัน

### 3. ประสิทธิภาพและการออกแบบ (Performance & Responsive UI)
* **Responsive Layout**: แสดงผลได้อย่างสวยงามทั้งบนสมาร์ตโฟน แท็บเล็ต และคอมพิวเตอร์
* **โหมดมืดอัตโนมัติ (Dark Mode / Light Mode)**: ปรับเปลี่ยนตามธีมของระบบผู้ใช้
* **Sticky Section Navigation**: แถบนำทางด้านบนช่วยให้เลื่อนข้ามไปยังส่วนต่างๆ ได้ทันที
* **Visibility-aware Smart Polling**: ระบบดึงข้อมูลอัตโนมัติจะหยุดทำงานชั่วคราวเมื่อผู้ใช้ไม่ได้เปิดแท็บหน้าจอ เพื่อประหยัดแบนด์วิดท์และทรัพยากรเครื่อง
* **ตัวนับผู้ชมสด ("กำลังดู N คน")**: แต่ละแท็บส่งสัญญาณทุก 30 วินาที นับแท็บที่ส่งภายใน 70 วินาที ออกจากหน้าแล้วหักทันที (sendBeacon) — เก็บเฉพาะรหัสสุ่มต่อแท็บ ไม่เก็บ IP / คุกกี้
* **ประหยัดแบนด์วิดท์ของเซิร์ฟเวอร์**:
  * ภาพ CCTV นนทบุรีย่อเป็น 480 px ด้วย GD (~20 KB แทน ~65 KB) และใช้ URL แบบมีเวอร์ชัน (`&v=<mtime>`) ที่เบราว์เซอร์แคชได้ถาวร — โหลดใหม่เฉพาะกล้องที่มีภาพใหม่จริง
  * ภาพปากเกร็ดเขียนไฟล์ใหม่เฉพาะเมื่อภาพเปลี่ยน เบราว์เซอร์จึงไม่โหลดซ้ำทุกนาที
  * ภาพกล้องออฟไลน์ (จอสีฟ้าของ Milestone) ถูกตรวจจับและไม่นับเป็นภาพใหม่
  * ตัวดึงภาพเบื้องหลังมีได้ทีละตัว (flock) ดึงพร้อมกันสูงสุด 4 ภาพ (curl_multi) และพักกล้องที่ดึงไม่สำเร็จ 3 นาที

## 🔌 ระบบ API Backend & Caching

ทุก API Endpoint ออกแบบตามรูปแบบ **Cache-then-Scrape-then-Stale**:
1. **Cache First**: ให้บริการข้อมูลจากไฟล์แคชทันทีหากข้อมูลยังไม่หมดอายุ (TTL) เพื่อลดภาระเซิร์ฟเวอร์ต้นทาง
2. **Auto Refresh**: ดึงข้อมูลสดจากต้นทางเมื่อแคชหมดอายุ และบันทึกลงแคชใหม่
3. **Stale Fallback**: หากเซิร์ฟเวอร์ต้นทางไม่ตอบสนองหรือขัดข้อง จะนำข้อมูลแคชเดิมมาแสดงพร้อมระบุสถานะ `stale: true` เพื่อให้ระบบยังคงทำงานได้อย่างต่อเนื่อง
4. **Diagnostic Mode (`?debug=1`)**: แต่ละ Endpoint รองรับการส่งพารามิเตอร์ `?debug=1` เพื่อตรวจสอบสถานะการเชื่อมต่อ cURL, ข้อผิดพลาด และข้อมูลการประมวลผล

## 🚀 ข้อกำหนดและการติดตั้ง (Requirements & Setup)

### ความต้องการของระบบ (Prerequisites)
- **PHP 7.0+ หรือ PHP 8.x**
- Extensions ที่จำเป็น:
  - `curl`
  - `openssl`
  - `json`
- Extension ที่แนะนำ: `gd` — ใช้ย่อภาพ CCTV (ถ้าไม่มีจะส่งภาพขนาดเต็ม ใช้แบนด์วิดท์มากขึ้น ~3 เท่า)
- แนะนำ PHP-FPM (Synology Web Station ใช้อยู่แล้ว): ภาพกล้องจะถูกดึงเบื้องหลังหลังส่งคำตอบ (`fastcgi_finish_request`)
- บน Synology: เปิด extension ที่ **Web Station → Script Language Settings → PHP profile → Extensions**
- สิทธิ์ในการเขียนไฟล์ (Write permission) สำหรับโฟลเดอร์ `cache/`

### การติดตั้งและรันใช้งาน (Running Locally / Server)
1. นำไฟล์โปรเจกต์ไปวางใน Web Root ของ Web Server (เช่น Synology Web Station, Apache, Nginx, Docker หรือ VPS)
2. ตรวจสอบสิทธิ์การเขียนโฟลเดอร์แคช:
   ```bash
   chmod -R 777 cache/
   ```
3. หรือรันผ่าน PHP Built-in Server สำหรับการทดสอบ:
   ```bash
   php -S 0.0.0.0:8000
   ```
4. เปิดบราวเซอร์ที่ `http://localhost:8000`

### ตรวจสอบระบบ
เปิด `api/<endpoint>.php?debug=1` (เช่น `api/nonthaburi.php?debug=1`) — บรรทัดท้ายต้องเป็น `RESULT: OK` และหน้า nonthaburi จะบอกสถานะ cURL / php-fpm / GD

### ความจุโดยประมาณ (วัดจริง 30 ก.ย. 2569)
แบนด์วิดท์ที่เซิร์ฟเวอร์ส่งต่อผู้ชม 1 คน: ดูส่วนบน ~3 kbps, เลื่อนดูตาราง CCTV +~17 kbps (วิดีโอสดไม่ผ่านเซิร์ฟเวอร์)
ด้วยอัปโหลด ≥50 Mbps คอขวดคือ CPU ของ NAS — รองรับผู้ชม **พร้อมกัน** ราว 3,000–5,000 คน
